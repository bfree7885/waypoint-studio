# Cyber Briefing Engine

**Status:** Architecture V0.1  
**Package:** `design-system/signalterrain/intelligence/cyber/briefing/`  
**Runtime:** `design-system/js/signalterrain/wds-signalterrain-cyber-brief.js`  
**UI:** `apps/signalterrain/cyber/brief.html`

---

## Mission

Transform cybersecurity information into a calm, explainable daily briefing that answers:

> What should I pay attention to today?

Not an alert flood. Not fear marketing. Every conclusion shows its reasoning.

---

## Philosophy

| Prefer | Avoid |
|--------|-------|
| Clarity and context | Alarm fatigue |
| Honest uncertainty | Clickbait |
| Actionable learning | Artificial urgency |
| Transparent contributions | Black-box scores |

SignalTerrain should **reduce anxiety**, not increase it.

---

## Architecture

```
Entities (sample / ingest) ──► transparent priority engine
         │
         ├── audience profile (emphasis only)
         ├── previous snapshot (change detection)
         └── scenario filter (demo / quiet windows)
                    │
                    ▼
            generateBrief()
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
   section fill   reading    tone check
   + empty states  queue     (forbid phrases)
```

### Modules

| Artifact | Role |
|----------|------|
| `sections.json` | Ordered brief sections + dashboard panel labels |
| `audience-profiles.json` | Emphasis multipliers — facts unchanged |
| `empty-states.json` | Useful copy when a section has no items |
| `tone-rules.json` | Forbidden / preferred language |
| `schema-brief-v0.1.json` | Brief document contract |
| `schema-brief-item-v0.1.json` | Explainable item contract |
| Priority runtime | Labeled factor contributions (no mystery totals) |
| Ingest `detectChanges` | Timeline awareness vs prior snapshot |

---

## How items are selected

1. Start from the cyber entity graph (samples in V0.1).  
2. Apply an optional **scenario filter** (quiet day, Patch Tuesday, etc.) — documented, not hidden.  
3. Score each entity with the **priority engine**.  
4. Apply **profile emphasis** as an explicit `profile_emphasis` contribution when the multiplier ≠ 1.  
5. Fill each section with filters on kind / band / changes / watch fields.  
6. Empty sections keep `empty: true` and a message from `empty-states.json`.

There are **no hardcoded daily summaries**. Headlines and narratives are composed from counts, profile hints, and scenario labels at generation time.

---

## Sample scenarios

| Scenario | Intent |
|----------|--------|
| `quiet-day` | Low-noise window; force empty active exploitation |
| `patch-tuesday` | Patch / advisory emphasis |
| `critical-disclosure` | Teaching case around a critical CVE |
| `ransomware-campaign` | Campaign literacy for small-business emphasis |
| `cloud-outage` | Infrastructure-heavy day; cyber volume may be quiet |

Samples live under `briefing/samples/*.brief.json` and are **generated by the engine**, not hand-authored prose.
