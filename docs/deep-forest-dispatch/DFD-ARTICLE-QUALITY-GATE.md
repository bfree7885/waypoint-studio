# Deep Forest Dispatch — Article Quality Gate

**Purpose:** Operational checklist every new DFD article must pass before owner review.  
**Use after:** research → ledger → draft → visuals → render  
**Sibling docs:** `strategy/DFD-ARTICLE-PRODUCTION-WORKFLOW.md`, `PRODUCT_STANDARDS.md`

Pass/fail only. No numeric scores.

---

## SCIENCE

- [ ] Central mechanism is accurate against the source ledger (not against the article’s own prose)
- [ ] Important claims are caveated where conditions vary
- [ ] Does not oversimplify into a single buzzword (“bacteria,” “the cloud isn’t moving,” “always burns off”)
- [ ] Distinguishes this mechanism from look-alike phenomena where readers will confuse them

## SOURCES

- [ ] Source ledger exists under `data/deep-forest-dispatch/ledgers/`
- [ ] Authoritative sources (agency / peer-reviewed / university) support material claims
- [ ] No fabricated citations
- [ ] On-page sources are readable and restrained (details/summary — not a paper front-matter)

## ORIGINAL VALUE

- [ ] Page would still deserve to exist with **zero** search traffic
- [ ] Waypoint original visual/data asset carries the causal chain (not decoration)
- [ ] Answer to “what’s here that a generic SERP summary lacks?” is obvious in under 30 seconds of scrolling

## WRITING

- [ ] Opening establishes the phenomenon before encyclopedia orientation
- [ ] Tight: no length for SEO; cut restated visuals and templated closings
- [ ] No AI-farm tells: “Imagine…,” “Did you know…,” “Whether you’re…,” keyword stuffing, fake excitement
- [ ] Section structure is driven by *this* story — not a copy of the last article’s outline
- [ ] Ending lands; does not summarize the whole piece again

## VISUALS

- [ ] Hero shows the phenomenon (or the clearest authoritative view of it)
- [ ] No duplicate hero/body image unless the second crop teaches something new
- [ ] Original graphic: publication-quality, restrained labels, readable on mobile
- [ ] Every major image either shows or explains — no decorative stock
- [ ] Provenance/credit present for non-Waypoint assets

## MOBILE

- [ ] Realistic phone width (~390px): no overflow, no tiny diagram labels
- [ ] Headline wrap and hero crop acceptable
- [ ] CTAs tappable; sources usable
- [ ] Diagram full-bleed or otherwise readable without pinch-zoom gymnastics

## SEO

- [ ] Human title; sensible SEO title if different
- [ ] Meta description, canonical, OG, Article JSON-LD
- [ ] Sitemap entry
- [ ] Image alt text honest
- [ ] **No VideoObject** unless a real public video ID exists
- [ ] Prose not rewritten for keywords

## PROVENANCE

- [ ] Asset README / credits list NASA/USGS/etc. IDs where applicable
- [ ] Educational diagrams labeled as Waypoint editorial
- [ ] Licensing compatible with site use

## INTERNAL LINKS

- [ ] Related stories share a real conceptual family (airflow, water, observation…)
- [ ] Not fully cross-linked “everything to everything”
- [ ] Links help a curious reader continue — not SEO scaffolding

## WAYPOINT CONNECTIONS

- [ ] Only real products; no invented forecasts/detectors
- [ ] Copy is observational (“watch ingredients”) not promotional
- [ ] Prefer ≤2 connections unless a third is clearly earned
- [ ] Existing analytics hooks only (`DFD_*`)

## AI-SLOP CHECK

- [ ] Does not share identical paragraph rhythms / CTA language with sibling articles
- [ ] No formulaic “Explore further” / “Why it matters” block unless the story needs it
- [ ] Em dashes, rhetorical questions, and asides used sparingly
- [ ] Would a careful reader guess “batch-generated”? If yes — rewrite until no

## LIBRARY CARD

- [ ] Card image is the phenomenon, not a leftover crop
- [ ] Title and location line clear at library scale
- [ ] Coexists with video-companion and article-first stories without looking like a different product

---

## Batch rule

A batch is **ready to scale** only if every article in it clears this gate and an owner/editor agrees the floor is worth repeating.
