# Sheds RADAR P1 — Continuous Static Base Landscape

**Status:** Implemented on Studio (feature-gated prototype path). **Not** published to shedhunting.org.  
**Decision (inspection):** B — small explicit base-landscape scoring refactor.  
**Module:** `apps/shed-hunting/js/sheds-radar-base-landscape.js` (`WaypointShedsRadarBaseLandscape`)  
**Viewport wiring:** `apps/shed-hunting/js/sheds-radar-p0.js` (`radar-p1.0`)

## Purpose

Answer:

> Before today’s weather/conditions are applied, which parts of this landscape are relatively more interesting to search based on persistent geographic characteristics we can legitimately measure?

This is the **static geographic foundation** underneath future condition dynamics:

```
STATIC BASE LANDSCAPE  +  P2 TIME-VARYING CONDITIONS  =  TODAY'S RELATIVE SEARCH INTEREST
```

P1 implements **only** the static base.

## Architecture

| Layer | Role |
| --- | --- |
| Pack sample | NLCD → structure, `edgeM`, `slopeDeg` (~90 m) |
| `WaypointShedsRadarBaseLandscape` | Continuous analytical score `[0,1]` + factors + confidence |
| `WaypointShedsRadarP0.buildBaseField` | Viewport×pack field of `landscapeScore` |
| Terrain enrich | Aspect / `featureKind` for **conditions only** (not base score) |
| Phase 1 `evaluateCell` | Unit-scale base + scaled condition deltas (`1/3`) |
| Heat layer | `renderMode: "radar-interest"` bilinear display |

**HabitatGis** remains for legacy Search Area / GIS channels. RADAR does **not** collapse through GIS bands `{stronger,some,limited}` → `{2,1,0}`.

## Score formula

```
landCombined = clamp01(coverBase(structure, nlcd) + transitionBoost)

if structure == water:
  score = 0
else if slope available:
  score = clamp01(0.80 * landCombined + 0.20 * slopeContext)
else:
  score = landCombined   # missing slope ≠ low; status = partial
```

Weights `W_LAND = 0.80`, `W_SLOPE = 0.20` are **named model parameters**, not scientific constants.

### Cover bases (searchability / geography — not deer preference)

| Structure | Base |
| --- | --- |
| forest | 0.44 |
| open | 0.43 |
| wetland | 0.43 |
| agriculture | 0.40 |
| developed (fallback) | 0.08 |
| developed NLCD 21 | 0.10 |
| developed NLCD 22 | 0.09 |
| developed NLCD 23 | 0.06 |
| developed NLCD 24 | 0.05 |
| water | 0.00 |
| other / unknown | 0.22 |

Searchable vegetation types are deliberately **flat** — no “forest > open because deer prefer forest.”

### Transition

- Pack `edgeM`: Chebyshev distance to forest↔non-forest (`forest={41,42,43,90}`).
- Boost **only** when current cell is searchable (`forest|open|agriculture|wetland`).
- Developed / water: **no** transition boost.
- `edgeM ≤ 90`: `boost = 0.30 × (1 − edgeM/90)`.
- Explainability: **“Land-cover transition nearby”** (not “forest/open” unless proven).

### Slope context (mild)

| Slope | Context value | Meaning |
| --- | --- | --- |
| &lt; 2° | 0.50 | Nearly flat |
| 2–12° | 0.65 | Moderate — strongest mild boost |
| 12–25° | 0.45 | Steeper |
| ≥ 25° | 0.20 | Very steep — search practicality |

### Water / developed

- **Water → score 0** (search practicality — not “deer avoid water”).
- **Developed** suppressed by NLCD intensity when available.
- Language: “not treated as searchable ground” / “reduced for search practicality.”

## Excluded from static score

Aspect · featureKind · weather · freeze/thaw · snow · temp trend · season · Search Area · observations · Hunt history/tracks · ownership · PA SGL · roads/trails.

Aspect remains available for **condition** interactions only.

## Confidence vs score

| Situation | Score | Confidence |
| --- | --- | --- |
| Full pack sample + slope | computed | moderate |
| Pack, missing slope | land-only (`partial`) | terrain limited — **not** forced low |
| No sample | `null` / unsupported | none — **not** zero |

**Missing ≠ low.**

## Display labels (explainability only)

Continuous score remains the store. Labels for humans:

| Score | Label |
| --- | --- |
| &lt; 0.34 | Lower |
| &lt; 0.62 | Moderate |
| ≥ 0.62 | Stronger |

Do not re-collapse the analytical base to three categories.

## Condition layer adapter

Phase 1 `evaluateCell` accepts `cell.landscapeScore` (`scale: "unit"`).  
Modifier eligibility (`solar_searchability`, `snow_practicality`) is unchanged; deltas are scaled by `UNIT_MODIFIER_SCALE = 1/3` so they remain one relative step on a unit base.

Static base is **byte-deterministic** across Frame A/B; only the painted condition-aware surface changes.

## Analytical resolution

~90 m (pack / viewport cell). Bilinear paint is **visual only**.

## Pike distribution evidence

Locked viewport (P0 fixture): center ≈ 41.3091, −74.7835 · z13 · 50×50 · ~90 m.

See `docs/sheds/samples/radar-p1/distribution-report.json` (generated by `automation/test-sheds-radar-p1.mjs`).

Acceptance intent: materially continuous (&gt;3 unique values), not ~67% identical top-band cells, coherent clustering, water/developed suppressed.

## False-precision / honesty

- Not find probability / encounter rate.
- Do not expose model decimals as biological precision.
- Pack edge cannot prove opposite-side class — keep conservative transition copy.

## Known Pike-pack limitations

- Edge includes forest↔developed/water; no pack rebuild in P1.
- Woody wetlands treated as forest for edge mask (pack definition).
- Open land is rare in the proof AOI — Stronger share can remain elevated without being a tuning failure.
- ~90 m cannot support microterrain claims.

## P2 boundary (do not implement in P1)

Live weather product radar · time playback · forecast/historical frames · SNODAS · nationwide pipelines · personal-history weighting · access scoring · production deploy.
