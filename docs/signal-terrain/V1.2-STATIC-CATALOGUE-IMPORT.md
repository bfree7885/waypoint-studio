## Official static source concept

SOTA publishes a static summit list commonly named `summitslist.csv`. Public importers document a title line:

`SOTA Summits List (Date=… Version=…)`

followed by a header row whose columns are mapped **by name**, not by position. Typical names include `SummitCode`, `AssociationName`, `RegionName`, `SummitName`, `AltM`, `AltFt`, `Longitude`, `Latitude`, `Points`, `BonusPoints`, `ValidFrom`, `ValidTo`, plus activation columns when present.

Association and region **codes** (for example `W2` / `GC`) are usually embedded in `SummitCode` (`W2/GC-001`). The importer parses those codes. It does not invent them. It does not assume US state abbreviations are SOTA region codes.

A human downloads the file through a permissible path and passes a **local path**. This repository does not retrieve it.

## Manual-download requirement

```
node scripts/signalterrain/import-sota-summits.mjs \
  --input /path/to/summitslist.csv \
  --dry-run
```

`--input` must be a local file. HTTP(S) URLs are refused. There is no download flag.

## Importer usage

```
node scripts/signalterrain/import-sota-summits.mjs \
  --input /path/to/summitslist.csv \
  --out tmp/signalterrain/generated-summit-packs \
  --region W2/GC \
  --region W2/NJ \
  --association W2
```

`--region` and `--association` may be repeated. Generation **requires** at least one of them so a worldwide list cannot dump every association into staging by accident. Use `--dry-run` first to see which codes the file actually contains. Do not assume region codes from conversation.

Default `--out` is `tmp/signalterrain/generated-summit-packs/` (gitignored). Writing into `apps/summit-signal/data/` is refused.

`--json` prints a machine-readable report.

## Dry-run usage

```
node scripts/signalterrain/import-sota-summits.mjs \
  --input /path/to/summitslist.csv \
  --dry-run
```

Reports:

- source filename, byte size, SHA-256
- title line
- mapped / unmapped headers
- total source records, valid unique records, invalid rows
- associations and regions with counts
- sample summit records
- exact duplicates
- conflicting duplicates

Writes **no** pack files.

---

## Source hash

SHA-256 of the **raw file bytes**. The hash is copied into every generated pack’s `source.sourceHashSha256` and into `import-report.json`. That identifies exactly which summit-list snapshot produced a pack.

---

## Regional filtering

Filters use SOTA association/region **codes** from the file:

- `--region W2/GC` — one pack
- `--region W2/GC --region W2/NJ` — those packs
- `--association W2` — every region in that association

Do not pass state names (`Pennsylvania`). If the file has no `W2/NJ`, dry-run will not list it; do not invent the code.

---

## Staging output

Each selected region becomes `ss-summits-{assoc}-{region}.json` plus `import-report.json`.

Packs follow the V1.1 fixture shape (`source`, `region`, `summits`) so `SignalTerrainSotaModel.validatePack` can accept them later. They are **not** listed in `ss-summit-catalogue.json`.

---

## Validation

Invalid rows are **reported**, not silently dropped without a log:

- empty or malformed summit reference (`ASSOC/REGION-NNN`)
- non-numeric or out-of-range latitude / longitude
- non-numeric elevation or points when those cells are present
- missing elevation
- missing association/region (column or parse-from-ref)
- field length > 2048
- NUL bytes in the file (rejected entirely)

---

## Duplicate handling

Identity is the summit reference.

- Exact duplicate rows that **agree** on material fields: keep the first; count as removed.
- Same reference with **conflicting** name, coordinates, elevation, points, association, or region: **fail generation** and report reference, source rows, and conflicting fields.

Do not guess which row is correct.
