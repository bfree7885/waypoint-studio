# SignalTerrain V0.3

**Status:** In development · unpublished · `noindex`  
**App route:** `/apps/summit-signal/` (do not occupy `/apps/signalterrain/`)  
**This release:** Plan the hike — user-selected access + pedestrian route + USGS 3DEP profile

> **SignalTerrain (SOTA/outdoor, unpublished) is a new product definition and is not the retired SignalTerrain Cyber product.**

> **Mapped trail, trailhead, and parking features are candidate access information derived from OpenStreetMap and may be incomplete or outdated. Verify current access conditions before travel.**

> **Calculated hikes are Valhalla pedestrian routes toward the SOTA summit coordinate. They are not a recommended trail, not hike-track recordings, and not proof of a valid SOTA activation.**

V0.2 remains the OSM access layer. V0.3 adds **how can I hike from this access point toward the summit?** after the user deliberately chooses a start.

---

## Scope

Included:

- User selects a V0.2 mapped parking area or trailhead (**Start hike here**)
- Dedicated routing provider (Valhalla pedestrian)
- Dedicated terrain provider (USGS 3DEP)
- Calculated route drawn distinctly from OSM trail fragments
- Route distance (not straight-line)
- Elevation profile, cumulative gain/loss when 3DEP succeeds
- Estimated time from the router (rounded)
- Change access point and recalculate without reloading
- Honest routing/elevation failure states
- Core SOTA + V0.2 access still work if V0.3 providers fail

Not included:

- Automatic “best” trailhead/parking
- Activation-zone polygons
- Trail difficulty, reviews, land ownership
- Weather, spots, alerts, logging, GPX, offline routing
- AllTrails / Gaia / onX scraping

## Pre-implementation choices

### Routing providers evaluated

| Provider | Hiking behavior | Key | Production |
|---|---|---|---|
| **Valhalla** (selected) | `pedestrian` costing with `use_trails` and `max_hiking_difficulty` | None for self-host; FOSSGIS demo is open | Self-host |
| OpenRouteService `foot-hiking` | Strong hiking profile (SAC scale) | **Required API key** | Self-host or key |
| GraphHopper `hike` | Trail-aware | **Required API key** | Self-host or key |
| OSRM foot | Easy, weak trail preference | Public instances exist | Not selected |

**Selected:** Valhalla pedestrian (`use_trails: 1`, `max_hiking_difficulty: 3`).

**Why:** No API key in the unpublished app; trail-preferring pedestrian costing; MIT-licensed engine; clear self-host path. OpenRouteService would be a good hiking profile but cannot ship a secret key in this repo.

**Live endpoint (opt-in):** `POST https://valhalla1.openstreetmap.de/route`

**Terms:** FOSSGIS Valhalla is **development/testing**, 1 req/s, not for production or high-traffic products. SignalTerrain default is a **labeled fixture**. Live is `?route=live=1`. Production must **self-host Valhalla** (or a licensed managed instance).

### Elevation sources evaluated

| Source | Resolution | Key | Notes |
|---|---|---|---|
| **USGS 3DEP ImageServer getSamples** (selected) | 1 m lidar in the Catskills extract; 1/3″ (~10 m) nationally | None | Authoritative US DEM |
| USGS EPQS | Point only | None | Too chatty for a route |
| OpenTopoData NED10m | ~10 m | None | 3DEP-derived, 100-point batches |
| Esri World Topo | Basemap | — | **Not elevation data** |
| Valhalla `/height` | Tilezen on the FOSSGIS host | — | Not USGS 3DEP |

**Selected:** USGS 3DEP `getSamples` along the calculated polyline (bilinear).

**Units:** meters (NAVD88-style 3DEP values). Display also in feet.

**Sampling:** 3DEP densifies the path (`sampleCount` ~80–180). Samples are sorted by `locationId` along the route. Horizontal interval is on the order of **30 m** (fixture ~177 samples on 5.75 km).

## Architecture

```
User-selected parking/trailhead  +  SOTA summit coordinate
        ↓
SignalTerrainSotaRoute  (ss-route-provider.js)
        ↓
Valhalla live  or  labeled fixture
        ↓
SignalTerrainSotaRouteModel
        ↓
Map hike polyline  +  Plan the Hike
        ↓
SignalTerrainSotaTerrain  (ss-terrain-provider.js)
        ↓
USGS 3DEP live  or  labeled fixture
        ↓
SignalTerrainSotaTerrainModel  (profile, gain, loss)
```

The UI does not contain Valhalla or 3DEP URLs. Routing failure never draws a straight line. Elevation failure keeps a valid route.

Destination model: `kind: "summit-coordinate"`, label **summit vicinity**. Reaching that coordinate is **not** claimed to be required for a SOTA activation. The same DEM provider can later contour a ~25 m activation zone; V0.3 does not draw one.

## Distances and elevation (do not conflate)

| Term | Meaning in V0.3 |
|---|---|
| **Straight-line distance** | Haversine from summit to a parking/trailhead (V0.2). Not a hike. |
| **Route distance** | Length of the Valhalla pedestrian geometry. |
| **Elevation difference** | End − start on the profile (net). Not shown as “gain.” |
| **Cumulative elevation gain** | Sum of smoothed rises along the route. |

---

## Ascent / descent

1. Sort 3DEP samples by `locationId`
2. 5-point moving average (noise filter)
3. Sum positive smoothed deltas as gain, negative as loss
4. Ignore only sub-centimeter float wiggles (`|Δ| < 0.05 m`)

This is **not** summit elevation minus parking elevation.

---

## Time estimate

1. **Preferred:** Valhalla `trip.summary.time`, rounded to 5 minutes, prefixed `~`
2. Else: `distance_km / 5 + gain_m / 600` hours, labeled as a SignalTerrain estimate
3. Else: unavailable

Not a personal pace model.

---

## Caching

- Route: memory, key `signalterrain-sota-route-v0:{summitId}:{osmType}/{osmId}:pedestrian`
- Elevation: memory, key `signalterrain-sota-elev-v0:{osmType}/{osmId}:{distance m}`
- Tab lifetime. `retrievedAt` is the age signal.
- Default runtime uses labeled fixtures so CI never calls live Valhalla or 3DEP.

---

## Failure states

Routing: `ok` · `no-route` · `unavailable` · `timeout` · `invalid-start` · `malformed`  
Elevation: `ok` · `partial` · `unavailable` · `timeout`

No-route ≠ unavailable. Elevation unavailable does **not** clear the route.
