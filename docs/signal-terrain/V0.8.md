# SignalTerrain V0.8

**Status:** Unpublished field-test increment. Not a public product. Not merged, deployed, or indexed.

**Runtime:** `/apps/summit-signal/` (do not occupy `/apps/signalterrain/`).

**This release:** Close the gap between planning and a real outing: inspect a mapped start, copy its coordinates, hand those coordinates to the phone’s Maps app, and hide the sheet without destroying the plan.

---

## Field-use audit motivation

V0.7 made an Activation Plan, but a phone-side audit of the same Slide and Hunter fixtures found that SignalTerrain still could not support the last metres of *getting to the trailhead*:

1. Tapping a parking marker immediately started the hike.
2. Closing the summit sheet called `clearSelection()` and destroyed the route, Activation Zone, and Activation Plan — so the map could not be inspected with the plan still in memory.
3. OSM `access` and `fee` tags were already ingested and then hidden.
4. Selected-start coordinates were not shown, copied, or handed to an external navigator.
5. Straight-line distance was easy to confuse with driving or hiking distance.

V0.8 is intentionally small. It is a **field-test access + drive-to-trailhead handoff**. It is not an in-app road-navigation system and it does not attempt offline field operation.

---

## Selected-start inspection

Parking and trailhead markers, and access-list rows, **inspect** a candidate. Inspection shows a START section with, where available:

- mapped feature name, or a neutral unnamed label
- feature type (`Mapped parking` / `Mapped trailhead`)
- latitude and longitude
- existing OSM access tag
- existing OSM fee tag
- OSM identifier as secondary provenance

Inspection does **not** calculate or replace the hiking route.

**Start hike here** is the only action that commits the route origin. Existing V0.3–V0.6 recompute behavior runs after that explicit action.

A selected candidate that has not been committed is visually distinct from the route origin (`is-inspect` vs `is-start`). Inspecting another candidate leaves the existing route, destination mode, Activation Zone, and Activation Plan intact.

### Unnamed features

Do not fabricate a name. Unnamed parking uses **Unnamed mapped parking**. Unnamed trailheads use **Unnamed mapped trailhead**. The underlying OSM id may appear as provenance.

Do not call any feature official, legal, recommended, or best unless a legitimate source establishes that claim. SignalTerrain does not.

---

## Mapped vs verified

OpenStreetMap tags are **mapped evidence**, not a verification that parking or access is currently legal, open, safe, or available. The existing OSM caveat remains on the Access panel:

> OpenStreetMap data may be incomplete. Verify access before travel.

Field Readiness for a mapped start remains **VERIFY**.

## Access / fee semantics

Relevant tags already on the normalized OSM feature are surfaced factually:

| OSM tag | UI |
| --- | --- |
| `access=yes` | Mapped access tag: yes |
| `access=private` | Mapped access tag: private |
| `access=customers` | Mapped access tag: customers |
| (absent) | Unavailable |
| `fee=no` | Mapped fee tag: no |
| `fee=yes` | Mapped fee tag: yes |
| `fee=seasonal` | Mapped fee tag: seasonal |
| (absent) | Unavailable |

`access=yes` is **not** translated as “Legal parking.” SignalTerrain does not infer current legality, road condition, seasonal availability, ownership, or permission.

Missing optional metadata does not block route planning.

## Coordinates

Displayed and copied as five decimal degrees (about 1 m), for example `42.00868, -74.42764`.

Copy Coordinates copies that start lat/lng only. It never substitutes the summit, trail centroid, nearest road, or Activation Zone entry.

Success and failure are announced (`Coordinates copied.` / `Copy is unavailable in this browser.` / `Coordinates unavailable for this mapped feature.`).

---

## Maps handoff

**Open in Maps** is a navigation handoff. SignalTerrain does not calculate a driving route, travel time, traffic, or a current-location-to-parking path.

Open in Maps hands the selected mapped access coordinate to an external navigation application. SignalTerrain does not verify that parking or access is currently legal, open, safe, or available.

Destination is the inspected/selected access feature’s own coordinates.

| Platform | Mechanism |
| --- | --- |
| iOS | `https://maps.apple.com/?ll=lat,lng&q=label` (`ll` is the destination; `q` is a label only) |
| Android | `geo:lat,lng?q=lat,lng(label)` |
| Other / desktop | Google Maps query URL using `query=lat,lng` only (name is not used as a geocode, so it cannot silently resolve to the summit) |

If coordinates are missing, or the browser blocks the handoff, the UI says so. Coordinates remain copyable.

## State-preserving panel behavior

**Hide/close panel ≠ clear selected summit / plan.**

Closing, collapsing, Escape (when the sheet is open), or the Close control hides the sheet. It does **not** clear:

- selected summit
- inspected candidate
- committed hike start
- destination mode
- route / elevation
- Activation Zone
- Activation Plan
- personal checklist

**Show plan** (map overlay) or tapping the selected summit marker reopens the same sheet. Changing to a different summit still clears the previous outing (existing V0.1 behavior). `clearSelection()` remains available as an explicit programmatic reset; it is no longer bound to Close or Escape.

At phone widths the map remains inspectable with route, AZ, summit, and start markers still drawn.

Straight-line distance on parking/trailhead candidates is labeled **straight-line to summit** so it is not mistaken for driving or hiking distance.

## Known limitations

- SignalTerrain does not route on roads and does not know whether the mapped start is reachable by car today.
- OSM access/fee tags can be wrong, stale, or missing.
- Maps handoff quality depends on the external application. Desktop browsers open a Google Maps query; phones use `geo:` or Apple Maps.
- Clipboard and `window.open` can be blocked; those failures are reported, not faked.
- Offline maps, weather, closures, land ownership, spots, logging, GPX, and hike tracking remain out of scope.
- FOSSGIS Valhalla remains development-only. CI uses labeled fixtures (no live SOTA, Overpass, Valhalla, or 3DEP).
- Only Slide and Hunter have access/route/AZ fixtures.
- SignalTerrain is **unpublished**.
