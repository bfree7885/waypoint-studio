## Field-test issue that triggered V1.1

The V0.9 unlisted field-test map (`https://bfree7885.github.io/waypoint-studio-site/apps/summit-signal/`) showed:

**“118 summits · Development fixture — real retrieved SOTA region W2/GC (Greater Catskills)”**

The map viewport, fitted to the W2/GC **axis-aligned envelope**, extended across New York, Pennsylvania, New Jersey, and surrounding states. Markers came only from the W2/GC fixture. Empty parts of that rectangle looked like:

**“These are the SOTA summits in the visible geographic area.”**

That was false. They were only the summits in the loaded W2/GC pack.

A concrete miss: High Point State Park / High Point, New Jersey is in the user’s practical Milford / tri-state planning area and appears in the user’s SOTA app, but SignalTerrain showed no corresponding summit.

## Permission posture

V1.1 stays inside the existing permission-safe development posture:

- Do **not** expand live SOTA API usage beyond the existing optional `?live=1` W2/GC fetch.
- Do **not** scrape SOTA websites.
- Do **not** add an automated connection to SOTA infrastructure.
- Normal field-test and CI load **only** committed fixtures.
- Commercial SOTA API use is still **not assumed permitted** (see `docs/signal-terrain/V0.1.md`).

Because no permissible source for broader SOTA summit records exists in-repo, V1.1 **does not invent** neighboring-region summits. It makes the loaded coverage honest and ready for additional **labeled packs** when the owner supplies them.

### Smallest safe data-acquisition step (not done in V1.1)

Owner-approved, one-time, labeled fixture retrieval of neighboring **W2** regions (association already documented as USA - NJ / NY) using the same development method already used for W2/GC — stored as additional `data/ss-summits-*.json` packs listed in `data/ss-summit-catalogue.json`. Confirm SOTA permission before any new retrieval. Do not scrape. Do not turn those fetches into default runtime/CI live calls.

## Summit catalogue architecture

```
Catalogue manifest  (data/ss-summit-catalogue.json)
        ↓
Regional packs      (deterministic JSON fixtures)
        ↓
validatePack
        ↓
normalize + provenance
        ↓
merge + dedupe by SOTA reference
        ↓
coverage hull from actual summit coordinates
        ↓
search / map markers / coverage UI
```

The data model no longer assumes a single W2/GC region. Each normalized summit keeps provenance: source, association, region, retrievedAt, fixture version, pack id.

**Option A — bounded multi-region catalog.** All listed packs load statically. Markers are the merged catalogue. The map does not imply that the viewport equals the catalogue.

## Honest coverage UI

- Status / footer describe **loaded packs**, not a single implied complete region.
- Muted **coverage hull** on the map (actual summit convex hull, not the SOTA region envelope).
- If the viewport is outside the hull: **Summit catalogue not loaded for this area.**
- If the viewport is only partly inside: **Visible map includes area outside the loaded summit catalogue.**
- Initial fit uses the hull, not the oversized envelope.

---

## Search honesty

Search spans **all loaded packs** (name, SOTA reference, region, association).

A miss shows **Not found in current summit catalogue** — not “this summit does not exist.”

## Deduplication and validation

- Merge dedupes by SOTA reference when coordinates agree.
- Conflicting duplicate references fail merge.
- Duplicate references inside one pack fail `validatePack`.
- Packs must have provenance, association, region, valid lat/lng, and elevation.
- CI runs this validation on the committed W2/GC pack and on synthetic malformed packs.
