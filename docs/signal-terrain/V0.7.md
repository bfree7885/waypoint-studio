# SignalTerrain V0.7

**Status:** In development · unpublished · `noindex`  
**App route:** `/apps/summit-signal/` (do not occupy `/apps/signalterrain/`)  
**This release:** Activation Plan + Field Readiness

> **SignalTerrain (SOTA/outdoor, unpublished) is a new product definition and is not the retired SignalTerrain Cyber product.**

> **SignalTerrain remains unpublished.** It is not in public navigation, the homepage, About/Support, or the sitemap. `noindex` and `robots.txt` Disallow stay in force.

> **Field Readiness represents the completeness of information available to SignalTerrain. It is not a safety score, recommendation, or statement that a SOTA activation will be valid.**

> **Geographic presence inside the mapped zone is not a valid SOTA activation.** Radio contacts and other SOTA rules remain the operator’s responsibility.

V0.1–V0.6 remain in force: summit map, OSM access, user-selected Route to Summit, 25 m terrain-derived Activation Zone, Slide and Hunter acceptance, Route to Activation Zone. V0.7 organizes that evidence into a field-oriented Activation Plan. It does not change the 25 m closed-contour rule, Slide AZ cell counts, Hunter AZ cell counts, or V0.6 routing geometry.

---

## Goal

Answer, for the currently selected summit:

**Can I understand and execute this activation plan?**

This is not a recommendation engine, not a SOTA validity checker, and not a generic checklist application. It is a synthesis of SignalTerrain evidence already available for the selected summit, selected access, selected destination mode, calculated Activation Zone, and GPS when present.

---

## Activation Plan model

`SignalTerrainSotaPlan` (`ss-plan-model.js`, version `signalterrain-sota-plan-v0`) builds a normalized plan from:

- selected summit (catalogue identity already loaded)
- selected access feature + OSM catalog status
- selected destination mode and calculated route / elevation
- calculated Activation Zone and route/AZ relationship
- GPS vs AZ geographic status
- personal checklist (local)

The plan does not copy provider-specific Valhalla, Overpass, or 3DEP raw objects into the UI. Downstream surfaces (field UI and Copy Plan) render from this model.

Minimum fields:

- summit identity (name, reference, points, elevation, grid, coordinates when known)
- access state (selected feature, mapped type wording, OSM provenance, catalog status)
- hike / route state (destination Summit vs Activation Zone, distance, gain/loss, duration, sources)
- Activation Zone state (availability, 25 m threshold, terrain source, route entry, GPS)
- location state
- field-readiness rows
- unresolved verification items
- personal checklist
- snapshot rows
- plain-text copy payload
- `generatedAt` and `version`

## Readiness / status semantics

Field Readiness classifies **information completeness**, never safety or advisability. There is no numeric score.

| State | Meaning |
| --- | --- |
| **KNOWN** | SignalTerrain has a usable value from an existing provider. |
| **UNKNOWN** | The operator has not yet supplied or selected the input (for example, no start selected). |
| **UNAVAILABLE** | A provider ran and did not return a usable result. |
| **VERIFY** | A mapped candidate exists; legality / current conditions are not established. |
| **NOT INTEGRATED** | This product area is intentionally out of V0.7 (weather, radio conditions). |

Deterministic examples:

- no access feature selected → ACCESS = UNKNOWN
- mapped OSM parking or trailhead selected → ACCESS = VERIFY
- route provider returned a valid route → ROUTE = KNOWN
- AZ fixture/engine succeeded → ACTIVATION ZONE = KNOWN
- weather / radio conditions → NOT INTEGRATED

Mapped OSM parking is never labeled “Parking confirmed”, “Legal parking”, or “Official trailhead”. Wording is “Mapped parking candidate” / “Mapped trailhead”.

---

## Unresolved-item logic

**Verify before you go** is generated only from actual missing or uncertain knowledge:

- no start selected → select a mapped parking/trailhead
- mapped OSM start selected → verify parking/access legality and trail/access conditions
- access catalog unavailable → mapped access data unavailable — verify independently (does **not** mean access does not exist)
- empty OSM search → no mapped parking/trailhead in this search area; OSM may be incomplete
- route unavailable → hiking route unavailable — verify navigation independently
- AZ unavailable → Activation Zone unavailable — verify independently
- always, in V0.7: weather not checked; radio conditions not checked; offline navigation not confirmed

Do not emit alarming warnings without evidence. Absence of OSM data is not treated as proof that a trail or parking area does not exist.

## Checklist behavior

**Personal field checklist** is operator-controlled packing. It is not “SOTA Required Equipment.”

Starter items: Radio, Antenna, Power/battery, Logging method, Water, Navigation backup, Appropriate clothing.

Check/uncheck in the Activation Plan. Reset restores the defaults for that summit.

---

## Persistence

Checklist state is stored in `localStorage` under `signalterrain-sota-plan-v0:checklist:{summitId}`. Scope is per summit. There is no account, cloud, or sync. If `localStorage` is unavailable, an in-memory fallback is used for the session.

---

## Copy Plan

**Copy Plan** writes a plain-text summary suitable for notes or a text message. It is not social sharing. Missing fields are stated as Unavailable / Not selected. The text includes the planning-aid sentence and does not claim a valid activation, a recommended outing, or confirmed parking.

---

## GPS / field state

When GPS is granted and the AZ is available:

- Inside mapped Activation Zone
- Outside Activation Zone

When GPS is unavailable: **Location unavailable**. The rest of the plan remains usable. GPS is not required to open or copy an Activation Plan.

---

## Failure isolation

- Access failure: summit and AZ remain; ACCESS = UNAVAILABLE
- Routing failure: access and AZ remain; ROUTE = UNAVAILABLE
- Terrain / AZ failure: route remains; ACTIVATION ZONE = UNAVAILABLE
- GPS failure: entire plan remains; location = unavailable

No single provider failure destroys the plan.

## Known limitations

- Weather is not integrated. It appears only as NOT INTEGRATED / “Weather not checked in SignalTerrain”.
- Radio intelligence (spots, alerts, propagation, bands, logging) is not integrated. Radio may appear only as a personal checklist item.
- Offline maps and offline routing are not implemented. The plan truthfully lists “Offline navigation not confirmed”.
- Route-to-AZ still uses only the selected-access Valhalla summit-route polyline (V0.6 limitation).
- FOSSGIS Valhalla remains development-only. CI uses labeled fixtures and must not call live SOTA, 3DEP, Valhalla, Overpass, or weather APIs.
- Only Slide and Hunter have access/route/AZ fixtures. Other W2 summits stay honestly unavailable unless live is requested.
- SignalTerrain is **unpublished**. No billing, public navigation, or SEO exposure.
