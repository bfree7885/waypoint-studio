## Acquisition gate

### Candidates examined

#### A. Deterministic data already in the repository

**Not sufficient.** Only `W2-GC`. High Point State Park / High Point, New Jersey is not among the 118 records. The Catskills peak **High Point B** (`W2/GC-015`) is a different summit.

#### B. Previously retrieved/static data already available to the project

**Not sufficient.** The only previously retrieved SOTA region fixture is W2/GC (2026-09-04). No neighboring-region JSON exists in git history.

#### C. Downloadable/public dataset whose terms permit intended development use

**SOTA public API (`api2.sota.org.uk`)** is the dataset used for W2/GC.

| Question | Assessment |
| --- | --- |
| Source | Summits on the Air API, `https://api2.sota.org.uk` |
| Access method | Documented HTTP JSON endpoints (V0.1 used `GET /api/regions/W2/GC`) |
| License/terms | [SOTA API Terms of Service](https://api2.sota.org.uk/docs/index.html), reviewed 2026-09-06 |
| Automated retrieval permitted? | **Not for AI-generated software without prior SOTA approval.** ToS: “No AI or Vibe-coding” — *no AI-generated software may connect to the SOTA API without prior approval.* Also: reasonable public usage tolerated; **no commercial usage** without a formal licence; designated point of contact / Reflector `API-consumers` group required |
| Redistribution in this unlisted development catalogue? | W2/GC already exists as a labeled development fixture with attribution. Expanding that pattern is a **human / SOTA-approved** act, not an AI runtime or AI retrieval |
| Commercial/public use | Separate SOTA licence. Not assumed. This app is still unpublished / unlisted |
| Date/version of terms review | 2026-09-06, `https://api2.sota.org.uk/docs/index.html` |

V1.2 instructions independently forbid solving this by connecting SignalTerrain to the live SOTA API, scraping SOTA/SOTLAS/third-party apps, bypassing access controls, or adding unauthorized runtime requests.

This agent therefore **must not** call `api2.sota.org.uk` to retrieve neighboring regions.

#### D. Other permissibly licensed geographic source

**OpenStreetMap** (ODbL) has a documented tag `communication:amateur_radio:sota` for SOTA references. That is OSM mapper data, not a SOTA API call.

It is **not sufficient for V1.2**:

- OSM’s High Point, New Jersey peak node does **not** carry a SOTA reference tag (public OSM node tags: name, `ele`, GNIS, Wikidata; no `communication:amateur_radio:sota`).
- V1.2 requires the exact High Point SOTA identity from a legitimate catalogue. OSM does not provide it.
- OSM tagging of SOTA peaks is incomplete relative to an official region list. Using it would invent a false sense of coverage and still fail High Point acceptance.

**Wikidata** has no dedicated SOTA identifier property found in this review. Wikipedia/GNIS describe High Point as a geographic peak, not a SOTA catalogue record. Geographic names and elevations **must not** be mapped to invented SOTA references.

#### E. Manually supplied records

**None supplied** with this request. No attached JSON/CSV packs, no owner-provided High Point record.

## Gate decision

**STOP. DATA ACQUISITION BLOCKER.**

No defensible source currently available to this agent can add neighboring SOTA packs or identify High Point’s SOTA reference without:

- calling the SOTA API from AI-generated software (ToS + V1.2 forbid),
- scraping (forbidden),
- or fabricating / inferring references (forbidden).

V1.1 honesty is preserved. Practical Milford-area coverage is **not** solved. That is the correct failure mode.
